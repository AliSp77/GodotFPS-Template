# Cartoon Terrain for the FPS project

This project folder brings the Studio's finite map data, generator, editor operations, and terrain geometry compiler into the FPS project. It requires **Godot 4.7.2 .NET** and the **.NET 8 SDK**. The necessary Studio source code and notices are included in this folder; the separate `cartoon-terrain-studio` folder is not required to compile it.

For a description of each generation setting and its effect, see [Generation settings](GENERATION_SETTINGS.md).

## Try the example

1. Open the FPS project with the Godot **.NET** editor and build the C# project using the editor's Build button. Wait for the C# assembly to reload.
2. Open `res://terrain/demo/terrain_demo.tscn` and run the current scene. The project main scene remains the existing Fractal Vault stage run.
3. The example includes a saved map resource, baked collision and navigation, the existing player, and an existing enemy. Escape releases/captures the mouse as in the FPS project.

The terrain's visual meshes are generated by background workers when the scene opens. The example's saved collision and navigation are already available while the visuals bake.

## Create or edit a map

1. Add a `CartoonTerrain` node to a 3D scene and select it. The project's editor configuration enables the terrain editor from `res://terrain/plugin.cfg`. If its dock is not visible after a build, restart the editor.
2. In the Inspector, create a new `CartoonTerrainData` in the node's **Data** property, or assign an existing one. You can also use **Create terrain data** in the dock, or import a Studio terrain JSON file.
3. Expand the data resource in the Inspector and edit its seed, dimensions, landscape, theme, outline, layout, and generation dials. Click **Generate map from these settings** in the resource Inspector, or **Generate from data settings** in the dock. Generation replaces the map in that resource and can be undone.
4. Save the data with **Save data resource** and save the scene. The terrain resource stores both the editable map and its generation settings. Save the resource again after edits.
5. Enable painting in the dock. Choose a tool and paint in the 3D viewport. Turn painting off to select and manipulate ordinary scene nodes. Selection uses a dragged rectangle; use Copy, Cut, Clear, and the Paste tool to place copied cells. Edit actions participate in the editor's undo/redo history.
6. After terrain edits, wait for the visual bake to finish, then choose **Rebuild collision** and **Bake navigation** in that order. Save the scene again to persist derived collision and navigation. Their stale status is shown in the dock and as node configuration warnings.
7. Place player/enemy `Marker3D` nodes and add them to the `cartoon_terrain_spawn` group. Use **Validate spawn markers** after the navigation map has synchronized. The first valid marker is the reachability reference.

One default cell is 2.5 m across and one height level is 0.6 m. Map geometry is centered on the terrain node. A saved Studio document can be imported or exported as JSON; the JSON extension includes `floorUsage` to preserve this layer.

## Reproducing a Studio map

The project calls the same vendored C# map generator as this version of Studio. Enter the same seed, width and height, landscape, theme, outline, layout and eight dial values in both applications. In particular, use the same **Any theme** or **Mixed regions** choice when applicable. An empty seed rolls a new seed and displays it; copy that displayed value to Studio to reproduce the map. The default size is 96 × 72 and Surprises defaults to 0.4.

The generated base consists of the tile and elevation cells in the saved resource or exported JSON. The Studio and project exports can differ in metadata and rendering even when those cells match. The terrain resource saves both the generated map and its settings; maps saved before settings were added retain their map data, but their original settings cannot be recovered automatically. Matching results require the same generator version in both applications.

## Collision and navigation

Solid terrain and structures use existing world collision layers as well as the named cartoon layer, so the existing player, enemies, weapon rays, and projectiles can detect them. Water and chasm boundaries block character movement, while bridge approaches are left open. Large rendered trees receive approximate trunk colliders; small plants remain decorative.

The navigation bake clips collision triangles to walkable terrain and bridge cells, excludes hazards, and accounts for tree trunks. Short collision ramps cover bridge-deck lips. Test slopes, tall height changes, narrow bridges, and complex structures with the actual enemies before using a map in a shipped level. Spawn validation uses the scene's world navigation map; other navigation regions in the same world can affect its result.

## Current limitations

- The world adapter uses the original geometry compiler, ground/rock shader functions, and vegetation placement data, but its water, trees, bushes, and lighting are simplified. It does not yet reproduce all Studio shaders, vegetation meshes, weather, or full look presets.
- The editor exposes the core tools, generation dials, brush/selection previews, and color tints, but not every Studio shape setting or diagnostic overlay.
- Finite maps are supported. Runtime terrain editing, endless streaming, and integration into Fractal Vault's `StageRoot`/stage catalog are not implemented.
- Collision and navigation rebuilds are explicit. Rebuilds should be checked after changing map data, and the scene must be saved to persist the derived nodes and navigation resource.
- JSON import accepts the Studio format, but older Studio versions ignore the `floorUsage` extension if they rewrite the document.
